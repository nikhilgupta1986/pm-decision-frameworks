# pm-decision-frameworks

A collection of decision-making frameworks I actually use as a Product Manager, not theory, each one is tied to a real decision I made, with the reasoning laid out so it's reusable beyond the specific situation it came from.

Most PM portfolios show *what* got shipped. This one is about *how* the decision got made, the criteria, the tradeoffs, and what I'd do differently.

## Frameworks

1. **[Feature Prioritization Under Pressure](./01-feature-prioritization-under-pressure.md)** - how I evaluate a mid-stream feature request against a committed roadmap
2. **[De-Risking a Technically Uncertain Bet](./02-de-risking-technical-bets.md)** - how I decide how much to commit to something I genuinely don't know is achievable yet
3. **[Diagnosing Low Adoption](./03-diagnosing-adoption-problems.md)** - why "people aren't using it" is usually two different problems wearing one symptom
4. **[Designing and Measuring Engagement Features](./04-engagement-metric-design.md)** - the metric framework I use before shipping anything meant to change user behavior

More frameworks will be added as I use and refine them. This is a working document, not a finished product.
